# 9. Transaction Ownership Correction (Quality-Review Finding)

The first implementation draft's shared fixture helper
(`_create_corpus_database()`) and the second-rebuild idempotency test
each called an explicit `conn.commit()`/`write_conn.commit()` immediately
after `TradeService.ingest_batch()` and after
`TradeService.rebuild_all_lifecycles()`. The final quality-review pass
identified this as a defect in test design, not merely a style
preference: both service methods already own and commit their complete
transaction internally via the pre-existing `_r5_write_transaction()`
context manager (`database/service.py`) - issuing `BEGIN IMMEDIATE` and
`COMMIT` themselves on success. A redundant caller-side commit could
silently mask a future regression in which a service method stopped
committing internally, since the test's own commit would paper over the
missing one and every "fresh connection" durability assertion would keep
passing for the wrong reason.

All three such calls were removed before the commit described in Section
3. The acceptance tests' fresh-connection durability proof now depends
solely on `TradeService.ingest_batch()`'s and
`TradeService.rebuild_all_lifecycles()`'s own internal commit behavior.
The final committed test file
(`tests/test_lifecycle_corpus_acceptance.py`) contains no executable
caller-side `commit()` or `rollback()` call anywhere - verified via
`rg -n "\.commit\(|\.rollback\("`, which matches only explanatory comment
text, never executable code. All 35 focused tests were rerun after this
correction with identical results (35/35 passing), confirming the
removed calls were pure no-ops against the current, correctly-implemented
production code.
